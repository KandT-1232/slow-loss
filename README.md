# 慢减（Slow Loss）—— 记录体重，AI 帮你看懂趋势

一个面向「反复减脂复胖女性」的减脂助手。**核心功能：每天记录体重 → AI 结合过去 7 天趋势，先安抚情绪、再给真实判断和建议**（涨了多半是水分，不撒谎安慰）。

不同于薄荷、Keep 等只卷「工具」（热量计算、食物库、运动课表），**慢减**专攻它们都没碰的「心理线」：用「温暖地说真话」的方式，帮用户走出「节食 → 反弹 → 自责」的死循环。

> **核心洞察**：体重波动的「慌」是复胖循环的触发点。看到体重涨就慌 → 极端节食 → 反弹 → 更焦虑。产品在「慌」的那一刻介入。

## 功能（三个触点）

1. **体重记录 + 分析（核心）** —— 记录体重 → AI 结合 7 天趋势，先安抚再给真实建议（涨了多半是水分、看趋势不只看单天）
2. **每日心理短语** —— 首页每天一句心理建设（如「不要怕吃，控制好量就行」）
3. **对话问答** —— 基于 RAG 知识库的减脂知识深度问答

## 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Dify（知识库 + RAG + 提示词编排） |
| 生成模型 | DeepSeek |
| 向量化 | bge-m3 |
| 前端 | 原生 HTML/CSS/JS 单页 H5 |

## 快速开始

1. 在 Dify 创建对话应用，导入 `系统提示词.md`（提示词）和 `知识库.txt`（知识库，按空行分段）
2. 复制 `config.example.js` 为 `config.js`，填入你的 Dify API 地址和 Key
3. 浏览器打开 `index.html` 即可

> `config.js` 已被 `.gitignore` 排除，不会提交到仓库。

## 设计原则：温暖地说真话

情绪价值必须建立在事实正确之上——话可以很暖，但内容不撒谎。比如用户说「昨天暴食了」，回应是「这一顿确实会有点影响，但一次不会毁掉你，别用绝食惩罚自己」，而不是冷冰冰地讲道理，也不是骗她「没影响」。

## RAG 的结论：产品决策，不是漏做

评测第 5 轮抓了 `retriever_resources` 证据：24 题全空，模型一直在用底模（DeepSeek）裸答，拿到 87.5%。这引出两个结论——①通用营养知识（热量、辟谣、生理常识）底模本来就会，知识库没有增量空间；②本产品的差异化「温暖地说真话」的心理线，已经写在系统提示词里，不靠 RAG 承载。所以「暂不接知识库」是产品决策，不是漏做。RAG 只有在装「模型拿不到、只有你有的」私有内容（比如用户自己的 7 天体重历史）时才值得上。

## 已知限制

- 「比 7 天前的差值」的基准，取的是 7 天窗口内**最早一条记录**，不是严格找 7 天前那天的值；记录有断档时，这个差值跨的实际天数会略小于 7 天。
- 体重 AI 分析目前只算「近 7 天」；1 月 / 3 月的时间窗只在折线图里展示，未喂给 AI。
